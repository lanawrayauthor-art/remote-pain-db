# SETUP — автооновлення бази і доступ для AI з будь-якого чату

## Суть архітектури

Чат сам по собі не запускає задачі за розкладом. Тому «авто» живе зовні,
а чат лише *читає* завжди свіжі дані за стабільними посиланнями:

```
[GitHub Actions: щопонеділка]  →  update.py  →  реліз "latest"
                                                     ↓ стабільні URL
        Claude Project / будь-який чат / інші моделі читають звідси
```

## Шлях А — повний автомат (GitHub Actions, безкоштовно) ✅ рекомендую

1. Створи репозиторій на github.com (**публічний** — тоді будь-яка модель
   читатиме дані за URL без логіна; дані й так публічні з Reddit).
2. Розпакуй архів бази і залий увесь вміст у репозиторій
   (через "Add file → Upload files" або `git push`). Папка `.github/workflows/`
   з файлом `update.yml` вже всередині — Actions підхопить її сам.
3. Один раз завантаж стартову базу: **Releases → Create a new release** →
   tag `latest` → прикріпи файл `db.sqlite.gz` (лежить поруч з архівом) →
   **Publish**. Це «насіння» — далі воркфлоу оновлюватиме його сам.
4. Вкладка **Actions** → workflow `weekly-db-update` → **Run workflow**
   (перший запуск вручну для перевірки).
5. Далі — щопонеділка 09:00 за Києвом усе оновлюється саме:
   делта-збір трьох сабредітів (з перекриттям 3 дні — ловить пізні
   коментарі), злиття з дедуплікацією, повний переекспорт, публікація
   у реліз `latest`.
6. У файлі `DATA_GUIDE_FOR_AI.md` заміни `lanawrayauthor-art/remote-pain-db` на свої — один раз.

Скрипти на чистому Python (без залежностей), тижнева делта — кілька хвилин
роботи, безкоштовних лімітів Actions вистачає з величезним запасом.

## Шлях B — локально, пів-автомат

Кожне оновлення = одна команда в папці бази:
```bash
python3 update.py
```
Планувальник, якщо хочеш без рук:
- **Windows:** `schtasks /Create /SC WEEKLY /D MON /ST 09:00 /TN PainDB /TR "python C:\шлях\update.py"`
- **macOS/Linux:** `crontab -e` → `0 9 * * 1 cd /шлях/до/бази && python3 update.py`

Мінус: комп має бути ввімкнений, і доступ з чатів — лише через ручне
вкладення файлів.

## Доступ для Claude у будь-якому чаті

**Рівень 1 — Project «Pain DB» (найзручніше для щоденної роботи).**
Створи проєкт і поклади у Knowledge: `DATA_GUIDE_FOR_AI.md`, `README.md`,
`manifest.json`, `pain_theme_counts.csv`, `pain_theme_by_sub.csv`,
`top_terms.csv`, `pain_posts.csv`, `pain_comments_part1.csv` і `_part2.csv`
(повний файл >30 МБ, тому в архіві лежить розрізаний навпіл).
Кожен чат у проєкті бачить це все одразу. Після тижневого оновлення заміни
файли в Knowledge (2 хв) — або не заміняй, а проси Claude тягнути свіже за URL.

**Рівень 2 — будь-який чат, навіть поза проєктом.**
Кидаєш Claude посилання виду
`https://github.com/lanawrayauthor-art/remote-pain-db/releases/latest/download/pain_theme_counts.csv`
— це *завжди* найсвіжіший тижневий білд. Для глибокої аналітики Claude
завантажує `db.sqlite.gz` у середовищі виконання коду і ганяє SQL по
повних 430+ тис. рядків.

## Доступ для інших моделей (ChatGPT, Gemini, …)

Ті самі стабільні URL: моделі з веб-доступом читають CSV напряму; моделям
без інтернету в пісочниці (наприклад, ChatGPT Code Interpreter) вкладаєш
завантажений файл вручну. `DATA_GUIDE_FOR_AI.md` написаний англійською
саме для цього — вкинь його першим повідомленням, і будь-яка модель знає
схему, join-ключі та застереження.

## Додати сабредіт у моніторинг

Відредагуй `data/subs.json` (напр., додай `"overemployed"`), зроби разовий
історичний збір за README, далі тижневик підхопить його автоматично.
